# CP2 首样本 CPU 独立审计

CP2/DP2 已完成一次 1500 恢复后的 10 步 warmup 和 30 步采样；结果为单次描述性观测，不能归因于 CP 策略。原 run 只读；本目录聚合表由原审计程序生成，未改旧 FSDP/full/off/selective 结果。复核脚本与完整占用记录留存于本地原证据；此包仅包含审计摘要、聚合结果和四份逐 rank 记录。

## 训练与恢复

supervisor complete、child/总 exit 0，物理卡 rank 0–3 为 4–7。四 rank 各有 1501–1540 共 40 条完整唯一记录；每步两 micro，mesh DP2/CP2/TP1。四 rank 报告各有 80 次原始读取，按 canonical slot 逐项核对 6000–6159；CP 对同一 DP 样本使用两个序列切片。首两步每 rank 2 micro 的四字段 SHA 均与固定 canonical 一致，prepared 切片检查标志均为真；后续以读取的样本序列和 loader cursor 验证，不声称后 38 步重做字段哈希。

attestation、create、冻结 supervisor、四份 target、external audit 与 release 的 SHA 链接一致；审计报告 passed，258 role 比较、source/target/groups/extra 和 checkpoint identity 标志均通过。恢复的四 rank scheduler 在 step 1500，最终 optimizer 三组均 step 1540、LR 1e-5，组成员及其余选项通过原合同验证；末态 loader yielded 1580、consumed 6160。末态报告没有单独保存 scheduler state，因此不把 optimizer step 当成对最终 scheduler 的独立直接证明。此审计复核归档证明，不再次重读模型 payload。

## Loss 归约口径

本地最终集成源码的 `text_trainer.py`、`base.py`、`runtime/metrics.py` SHA 与 1a source manifest 一致。源码中 `postforward` 调用 `mean_global_loss`，以 DP+CP group 归约 token 加权 loss；`TextTrainer.train_step` 累加两个 micro 的已归约 loss。观察到四 rank 的 loss 最大差 CP2 与 FSDP4 均 9.5367431640625e-7。故这里比较两个 run 的 rank0 原始 loss，不对 CP 副本再求和或再次平均。1511–1540 配对 CP2−FSDP4 signed mean 0.0000392914、MAE 0.000260242、最大绝对差 0.00176477；这是有限步骤的描述性数值，不代表梯度、参数整体或跨策略因果证明。
