**What does this PR do / why do we need it**:

普通 `Shard(0)` 将逻辑形状 `[1,64]` 分给两个 rank 时，本地形状分别为 `[1,64]` 和 `[0,64]`；现有 `full_tensor()` 仍进入等长分片重分布路径，两个 rank 得到不同的错误形状。`[3,64]` 的一般非整除情形还会触发通信尺寸不匹配。该问题已用不依赖优化器的双进程 Gloo 用例复现。

本修改选择在入口明确拒绝尚不支持的普通非整除分片：

- 在重分布进入 Partial 归约、RaggedShard 分流或缓存变换之前，同时验证源布局与目标布局。按每个张量维度的全局长度和所有相关 mesh 轴的累计分片数判断整除性。
- 同样覆盖直接 `DTensor.reduce_partial()` 入口，避免先归约再丢失全局形状，导致后续重建绕过检查。
- 所有 rank 使用相同全局元数据生成 `NotImplementedError`，错误包含全局形状、维度、长度及分片数。检查只读取已有主机元数据，不新增 collective、设备同步或张量分配。
- 保持合法等长分片、现有 `RaggedShard` 路径及 FSDP 私有填充通信的边界。本 PR 不实现普通非整除 `Shard` 的收集算法；直接访问本地分片仍可用于已有优化器验证。

基点：`hf1s/hyper-parallel:JT_dev@521d3a8a9aa62353327093ab1258ca2c22006e8b`，已包含 #180。本 PR 仅包含这一个问题的四个文件，独立一个 commit，不包含训练精度选项等其他补丁。
