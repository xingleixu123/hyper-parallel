**What does this PR do / why do we need it**:

CPU 后端的 `torch.cpu.current_device()` 返回字符串 `"cpu"`，现有 `get_device_id()` 却把它直接交给 JT 构建入口的 `torch.device(type, index)`，导致无加速器环境在模型设备构造阶段报 `TypeError: device(): argument 'index' (position 2) must be int, not str`。原有 JT CPU 测试把该 API 固定 mock 为0，遮住了接口错误。

本修改使 CPU 的 `get_device_id()` 返回无索引的 `None`，更新返回注解为 `Optional[int]` 和函数说明；CUDA/NPU 继续返回后端当前整数编号。JT 既有测试改为隔离后端可用性标志，让真实 API 参与随机初始化、参考权重加载和前后向训练验证；新增无索引 CPU 设备构造和两类加速器索引透传用例。

范围仅为这一接口缺陷，共3个文件、独立一个提交；不改变设备可用性判断、后端优先级、通信、损失和优化器。普通 HyperAutoModel 的 `_current_device()` 已有 CPU 特判，本 PR 不声称该入口原先也会失败。

基点为 `JT_dev@f637ef7ee4d4b416800716f1ebaaae7709b8a06a`，已包含#180。本次由125 NPU设备发现失败后回落CPU触发定位；**CPU接口修复不代表125 NPU发现问题已解决**，也不修改主机驱动或其他容器。
