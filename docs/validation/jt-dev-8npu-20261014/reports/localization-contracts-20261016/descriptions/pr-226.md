**What does this PR do / why do we need it**:

在 TP/PP 大于 1 时，Trainer 原先仅在当前 DP+CP 组内取步耗时和显存峰值，可能漏掉其他 TP lane / PP stage 的最慢或最大显存 rank。例如受控 DP2×CP2×TP2 回归的实际全局步耗时为 9 秒，rank0 原先只报告 7 秒；allocated/reserved 应为 13/17 GiB，却报告 6/7 GiB。这里只是单测反例，不是实测性能收益。

现在为 `_reduce` 增加私有的 `all_ranks` 选项，仅将步耗时、峰值 allocated、峰值 reserved 三次 MAX 扩大到全 world。tokens/s 使用修正的耗时；样本、token、loss 和梯度范数继续使用原 DP+CP 组，避免 TP/PP 副本重复统计。单进程仍直接返回本地值。

变更只有回调及其单测两文件，独立一个提交。基点为 `hf1s:JT_dev@f637ef7ee4d4b416800716f1ebaaae7709b8a06a`，包含 #180。已检查三个 Trainer 入口均由所有 rank 调用回调，并在私有方法说明 world 归约需要所有 rank 按相同顺序参与。collective 次数没有增加，三次资源 MAX 的参与范围扩大；其额外通信开销尚未实测。

现有耗时的 callback 计时范围、显存累计峰值语义和训练数值路径保持原状。本 PR 不代表完整 200 步精度、TP2 loss 偏差修复或最终资源收益验证。
