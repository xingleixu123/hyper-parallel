**What type of PR is this?**
/kind bug

**What does this PR do / why do we need it**:

JT 的 grouped SwiGLU 原先先把局部专家权重梯度写成 BF16/FP16，再交给 FSDP。即使 `reduce_dtype=float32`，归约也无法恢复已丢失的精度；不同 token 分区产生的局部舍入可被 Muon 放大。

增加默认关闭的 `model.config.expert_fp32_weight_gradients` 选项。启用后保持原来的前向与输入梯度 kernel，将权重梯度直接累加到参数实际布局的 FP32 `main_grad`，避免额外的全量转置 FP32 副本。显式传入所属参数，不通过张量 view 的 `_base` 猜测归属。要求本地连续专家张量、匹配的计算类型和 FSDP FP32 主梯度/归约策略；不满足契约时明确报错。

FSDP 在正常梯度消费点接收融合缓冲，并保留同一参数的普通 autograd 贡献；融合路径返回零占位梯度，避免重复累加。每次消费后清除缓冲引用和标志，兼容延迟同步、多微批、共享参数及重算。同步修正既有通用 grouped-matmul 融合路径的非零占位行为。

这是一项明确的数值精度选项，不默认改变既有训练配方。它不调整学习率、NS 系数/轮数，也不声称解决 TP 前向和输入梯度的舍入差异。新增使用说明随代码提交。
