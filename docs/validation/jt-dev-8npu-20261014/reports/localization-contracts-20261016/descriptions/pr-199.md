**What does this PR do / why do we need it**:

CP 分块输出损失需要为每个 MTP 深度使用自己的有效 token 分母，并与 TP/SP 输出头及 checkpoint 重放组合。现有回归未将“多个不同分母同时构图后联合反向”和“真实 CP/TP/SP 训练中的分块输出头”同时固定下来，后续修改可能静默退回完整词表投影或复用错误分母。

本 PR 基于已合入 #186 的 `JT_dev@f637ef7ee4d4b416800716f1ebaaae7709b8a06a`，仅修改两个测试文件：

- CPU 用例使用两层未来目标，有效 token 总数分别为 4、3，分别切为两个 CP 分片，使用同一个输出头；先构建全部目标，再联合反向。独立完整序列交叉熵作为参考，检查两组 hidden 梯度和共享输出头梯度，mock 计数归约覆盖反向且必须恰好发生四次。
- 四卡 worker 保留已有两种 MLA CP 路径、六种 TP/SP 组合、FA 检查、全部 loss/梯度/参数阈值；新增 TP1+CP4 与 TP2+SP+CP2，各执行两个 chunk48 训练步。按照当前 `enable_chunk_loss`/`chunk_loss_size` 配置，并观察输出头实际输入长度，确保测试确实进入分块路径。观测仅保存整数，hook 在 `finally` 中移除。

上游 #186 已实现本问题的生产功能，因此本次移除了原 PR 中重复的生产实现和已经由上游覆盖的单目标 CPU 回归。本 PR 最终交付的是该问题的独立回归保护，不把上游实现归为本 PR，也不修改生产损失公式、配置接口或训练配方。
