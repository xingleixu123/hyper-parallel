**What does this PR do / why do we need it**:

梯度累积原先按每个微批自己的有效 token 数归一化，再平均各微批。当两个微批分别有 1 和 3 个监督 token 时，真实 Trainer 路径给出 loss=5、梯度=10，而整批正确目标应为 loss=7、梯度=14。切换 DP/TP/CP 会改变累积微批数，因此即使全局样本相同，优化目标也可能改变。

本修改先准备完整 optimizer step，只计算一次整步分母，再让所有前向/反向微步共用。`TextParallelBatch.prepare_step` 仅缓存紧凑的源数据、标签和掩码，按消费顺序构造运行时 attention 输入，并及时释放已消费微批。仅支持 callable 的兼容路径使用 deque；迭代耗尽继续抛出原有 `StopIteration`，不会被生成器改写。

接口边界：新增 `TextParallelBatch.prepare_step`；直接调用 `TextTrainer.forward_backward_step` 时应传入已准备的模型和 loss 输入。已有 callable 数据提供者仍可使用；包装器应转发 `prepare_step` 才能保留紧凑准备路径，否则会暂存整步已准备输入，内存随微批数增长。相关契约已写入代码，不涉及官网页面修改。
