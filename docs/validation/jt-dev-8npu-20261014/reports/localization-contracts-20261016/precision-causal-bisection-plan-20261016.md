# 主 loss：受控替换与分段二分定位

用户在 2026-10-16 要求：消融有效后继续定位到具体算子、代码位置和触发条件；基线侧与并行侧都要对照最新 Megatron 和 MF PyNative 核查正确性。以受控替换、阶段/层二分获取证据，但不把“替换后 loss 更接近”直接当作根因或产品修复。

当前训练源固定为 `544526f7`。先完成该源码在共享机的原生 FSDP 200 步参考，并与 201 的同源候选比较。旧版改变 dtype 或补齐 head 行数的消融不直接替代新源码控制组，也不修改正在候卡的请求或 guard。

## 当前已有证据与不能越过的边界

- 历史 `18602c4` 配方 FSDP 的连续/续训及 off/full/selective 已有完整匹配结果；CP/EP/TP 主 loss 尚未全部达到 0.005。它们不能重标为 `544526f7` 的通过结果。
- 原生 FSDP/CP2 首步已采集的前向边界坐标相同，loss 标量导数相同，多个反向边界采样不同。它不能证明所有前向张量相同，也不能证明最早不同的采样边界是根因。
- FP32 Linear dX 在三步主 loss 有改善，但已有163步共有窗口最大差0.0120849609375，候选被否决。这说明必须区别短步定位和完整200步验收。
- 普通 Linear dW 直接 FP32 累加候选已被否决：FSDP 参考完成 200 步，CP2 的 1–159 步共有窗口主 LM 最大差为 0.0178985595703125，第 36 步首次超过 0.005。该候选不能作为已确认修复，不重复长跑同一配方；见 [实际前缀分析](f637-dense-wgrad-cp2-v1-prefix-analysis.json)。
- 旧源码 head 行切分的局部 VJP 重放确实观察到计算路径差异，但 padding 干预在三步训练中的效应方向不一致，未满足 200 步验收。不能从局部差异推导其已解释整个 CP/TP 漂移。
- 201 新源码完整 200 步候选及 checkpoint CPU 读回已经完成；125/129 仍受共享设备命名空间占用限制，尚无同源完整参考。MTP/aux 继续记录，当前先验收主 loss。

## 具体定位与两侧正确性的交付要求

消融发现只进入候选清单。确认一个具体问题前，应形成以下可复核证据，并写入其独立中文 issue 和单 commit PR：

1. **准确位置与触发条件。** 固定 JT 提交、文件、函数和行号，列出布局、shape、dtype、微批数、重算方式、同步模式和必要输入条件。比较双方同一逻辑 tensor 的切片、专家或 token，不能直接把不同物理 rank 的值当作同一对象。
2. **首次可信分歧。** 在怀疑算子的相同输入、参数、输出梯度和状态下，对完整目标 tensor 做有界分块比较，记录误差坐标、最大差和非零数；沿前向、局部 VJP、归约/裁剪、优化器更新收敛。共享 tensor hook 只能作为边界线索，不能冒充某个消费者的独立 VJP。
3. **两侧都验证。** FSDP 是实验参考，正确性仍须由数学目标与独立实现支持。核查并行分支的映射、归一化、归约顺序及状态更新，也核查 FSDP 基线是否有同类问题。基线和并行侧共同重复同一错误时，loss 相等不能证明正确。
4. **参考实现有版本和适用范围。** 使用 MF 官方 GitCode `master` 的 PyNative 路径和 Megatron 官方实际主线 `main`，固定提交、函数、源码行及文件 SHA；镜像落后时明确标注。分别比较目标归一化、局部 GEMM/主梯度/通信 dtype、优化器更新、重放副作用和 RNG/数据恢复。参考框架的 CUDA 或 MindSpore 行为不能直接充当 Ascend TorchNPU 的实测证明。
5. **因果干预与最小正式修复。** 保留未替换控制组及相邻无关区域对照，证明局部干预影响下一边界；不要用最终 loss、完整梯度或参数强制覆盖制造对齐。最终修复必须消除具体实现问题，并恢复普通训练路径；改变计算精度时要与同精度 FSDP 参考配对。
6. **独立回归与整体验收分开。** 问题本身要有修复前失败、修复后通过的可执行复现。主 loss 整体验收仍要求相应配置完整 200 步、全 8 rank 最大绝对差不超过 0.005；续训需比较 201–400 与独立连续 400 步。只完成短步或局部回归的 PR 必须明确其边界，不把组合修复的收益全部归给单个 PR。
7. **详细中文关联与成本。** 小 issue 写复现、预期/实际、根因与被排除假设；PR 写改动理由、固定参考链接、修复前后结果、相关重算/续训边界、显存和吞吐代价。小 issue 与 PR 互链并关联总 issue #202；源码保持每个问题一个 commit。

最新引用查询见 [官方主线查询记录](reference-correctness-heads-20261016-v2.json)：MF GitCode 与 GitHub 镜像当前并不同步，不能沿用旧镜像提交并称其为最新。实现文件的具体对照结论以随后完成的固定源码复核为准，单独的分支头查询不构成正确性论证。

## 先定位阶段，再定位层与算子

1. **固定边界状态。** 优先使用双方相同的初始化；必要时使用已验证FSDP检查点，明确参数、优化器状态、RNG、数据游标和累计token。比较同一逻辑batch及同一数学张量，先校验CP切片/TP分片/EP专家映射，不能按物理rank直接对比不相同的切片。
2. **阶段边界。** 在相同权重下比较选定完整张量：前向输出与loss输入、反向梯度在归约/裁剪前后、优化器更新及更新后主参数。首轮以有界分块扫描、最大误差/非零计数/稳定坐标为主；只对下一项干预必需的张量保存无损值。
3. **参考替换。** 对首次可信分歧所涉及的阶段，用同输入下的参考实现，或经身份校验的参考张量替换。在副本诊断中观察下一边界和下一步loss是否恢复。应保留未替换控制组，并做相邻无关区域的对照，防止将“强行把最终参数相等”误写成局部根因证明。
4. **按结构二分。** 若归约前后梯度明确不同，先以模块组（输出头/MTP、trunk、专家/共享专家）划分，再细分到层、Linear/Norm/Attention/MoE。相同输入下全阶段替换确有作用后，再替换一半模块；两半各自都有影响或均无单独影响时，保留交互可能，不假设误差作用单调。
5. **产品验证。** 以最小的真实实现修正替代诊断注入，恢复普通训练路径，并在相同配方下重新做完整200步、续训和相关重算检查。诊断注入的通过只能说明因果效应，不能直接算作最终产品验收。

## 代价与资源约束

- 短定位从1–3步开始；只有明确改善的候选进入200步。长跑已失败的同一候选不反复跑。
- 不保存200步全参数/全梯度。保存前按tensor形状/dtype估算容量，在125/129核对实际文件系统。分块顺序读取，单次只保留必要的参考边界；身份SHA、比较摘要、复现实验参数及必要原值留档，用完的传输包和工作副本及时清理。
- 受控参考与候选必须使用同一个数值配方、输入和可比环境。参考实现若改变计算精度，应生成匹配的新FSDP参考；不通过调LR、loss权重或容差制造对齐。
- 125/129每次确认释放后全局至少间隔1200秒；201通过同源跨机200步精度准入后可连续安排实验，无该间隔。各机启动前仍重新确认可用资源，不终止其他任务。8卡单轮限时900秒。二分无需每次长跑，更不能以后台常驻方式占卡。

## 采样语义复核补充

现有CPBackwardTrace在原张量上注册输入/输出梯度hook。共享输入可能同时服务多个消费者，hook观察到的是该张量收到的梯度；非重入checkpoint重放也可对同一输入再次注册观测。因此，不能把边界采样中的不同坐标数直接解释成某个算子的独立VJP。历史源码已完成真实head同输入、权重和输出梯度的局部VJP重放：行切分存在细小差异，但padding三步干预的主loss效果方向不一致，尚未确认其解释长程漂移。先建立544526f7的匹配原生参考；若仍有漂移，再据新证据选择完整输出梯度、loss缩放/归一化或共享分支合流的检查点，不把旧短步候选直接重跑成长实验。

本计划是待实际执行和结果校验的定位方法，不构成新的缺陷确认、精度通过或性能结论。
