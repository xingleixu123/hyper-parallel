# 精度定位记录：首步边界与裁剪归约

状态：继续定位，尚未达到全部并行 200 步绝对误差 0.005 的目标。正式基线仍包含 JT_dev `ad1c55379767d63ece7e084b0623340b37b83d93` 和 PR #180；当前六项修复的集成版本为 `ec2e16bce26e497519c573f0a8d87a538a329197`。

## 已观测到的边界

- EP2 和 CP2 的首步 LM、加权 MTP、加权 aux loss 与 FSDP 相同。TP2×EP2 首步已有前向差异，发生在第一次优化器更新前。
- 在 FP32 专家权重梯度与完整 FP32 NS 的三步诊断中，EP2 首步裁剪前 43 个受观测参数只有 4 个专家参数的数值摘要不同。30 个物理分片可直接比较的参数，其梯度摘要哈希完全相同；裁剪后这 30 个全部不同。小参数裁剪后最大绝对差为 `2.3283064365386963e-10`。
- EP2 原生梯度范数为 `22.47356414794922`，FSDP 为 `22.47356605529785`。43 个已观测参数用 CPU FP64 摘要合成的范数分别为 `19.70442407709252` 和 `19.70442407715463`。这不是全模型范数：未覆盖 `lm_head.weight`、`model.embed_tokens.weight`、`mtp.layers.0.eh_proj.weight`。
- CP2 在裁剪前的 43 个参数摘要均有差异，不能仅归因于裁剪。受观测小参数裁剪前最大绝对差为 `6.562471389770508e-05`。
- 参数摘要 SHA 包含物理分片身份。跨布局不能直接把 SHA 不同当作全局参数不同；`analyze_step1_parameter_evidence.py` 先核对初始摘要及有效分片，再允许直接比较。摘要统计量相同也不等于整个张量相同。

## 按证据优先级排查

1. **TP 前向输出投影。** 新增完整分块哈希证明：第一层 Q 投影输出 1,536 块、KV 投影输出 2,048 块、`o_proj` 输入 1,024 块全部一致，覆盖首步 8 个样本的全部序列和特征，缺失坐标为 0。随后 attention 输出的 10,240 个采样坐标最大差为 0.015625。差异已缩小到局部输出投影与其 TP 归约，尚不能只归因于通信。新增 `fp32_reduce` / `fp32_math` 两项消融；后者还会使用原生 FP32 autograd，所以仅首个 forward 能作为纯前向因果证据。
2. **CP 反向分片或累积的舍入。** 如果 BF16 权重梯度在局部计算后已发生舍入，只把最终归约设为 FP32 无法消除；应在相同输入的算子级局部梯度上复现。尚未据此提交稠密 Linear 修复。
3. **EP 梯度范数求和。** 如果裁剪系数把局部舍入传到全部参数，用更稳定的全局 L2 范数应先消除首步裁剪后稠密梯度差异，再改善后续轨迹。新增 FSDP/EP2 各三步诊断仅改变范数归约，保留原始阈值、epsilon 和梯度缩放。CPU FP64 拷贝与对象通信只用于定位，不能作为性能结果或最终实现。
4. **NS 实际矩阵批次。** FSDP8 与 TP2×EP2 的逐参数批次映射已比较，`changed=[]`。当前每个专家 NS 批次实际合并两个矩阵（trunk/MTP），稠密矩阵为 singleton 2D；这两种布局并没有观测到批次差异。此前合成 batch 8/4 探针仅揭示算子敏感度，不能解释为本次模型实际改变了批次。

`stable_clip_experiment.py` 已通过 CPU 精确参考、梯度输入不变、1/8 切分、零范数和非法范数检查。真实FSDP/EP各3步已完成：首步CPU FP64范数为22.47356466101615和22.473564660961692，均舍入至FP32的22.47356414794922；28个默认受观测参数在裁剪前后和更新后的摘要均一致（其中19个物理分片摘要可直接比较）。这些参数未覆盖全部专家参数，不能据此声称完整更新逐比特一致。3步LM最大差0.00014972686767578125、加权MTP 0.0002541542053222656，差异尚未消失。

生产选项短跑补充：FSDP8、EP2、CP2、TP2×EP2各3步均完成，全rank初始状态、输入、LR和步骤完整性检查通过。三种候选LM最大差分别为0.000461578369140625、0.0007839202880859375、0.000438690185546875；加权与去权重分量均低于0.005。这只是3步结论。

实际NS批次补充：EP2和CP2相对FSDP有4个变化，trunk第0层和MTP的`linear_qkv.weight`由[2112,5120] singleton变为batch2，trunk稀疏层和MTP的`mlp.gate.weight`由[8,5120] singleton变为batch2。TP2×EP2仍为无变化。逐矩阵NS消融把每个3D输入逐个调用原2D算法，保留系数、轮数、epsilon和dtype；原批次跟踪记录的是包装器之前的形状，真实执行次数另存`ns-single-matrix-rank*.jsonl`。

输出投影消融补充：只把BF16局部输出转FP32再做TP归约，首层attention最大差仍为0.015625。局部矩阵乘和归约都使用FP32时，相对匹配的FP32 FSDP参考，最大差为0.0009765625，相对L2为4.658849420155822e-5，非零坐标为4/10240；之后norm输出最大差0.0078125，MLP输出0.0625。该消融的autograd同样使用FP32，只能把首次前向作为纯前向定位证据。

合成行并行矩阵乘补充：4096×16384×5120与4096×12288×5120的BF16输入下，原生BF16全矩阵/分K计算在最终BF16输出约37.5%坐标不同；FP32局部结果再归约约0.05%–0.06%，GMM-add FP32累加约0.03%–0.04%。仍不能保证逐比特一致，单次计时不作为性能结论。稠密层FP32权重梯度消融已通过CPU与NPU算子参考，原BF16前向/dgrad保持精确相同；FSDP/CP各3步完成。CP裁剪前43个已观察参数摘要仍不同，小参数最大差6.56247e-5未消失，因此该权重梯度路径不是唯一来源。

纯TP合法性：直接将原TP2×EP2配置改为EP1时，规划器按设计拒绝融合gate/up沿融合维度连续切分，训练尚未开始；使用完整专家参数复制并同步修正MoE边界后3步已完成；200步正在执行。这不会获得专家权重的TP节省，不能标为专家TP切分。

## 融合 NS 算子诊断

完整 FP32 NS、原始 BF16、FP32 归一化后 BF16、融合 epilogue、融合 FP32 add 五种方案均保留原始五轮系数和 `norm + epsilon`。在本次合成输入中，FP32 add 的相对扰动敏感度降至 0.00414–0.01383，原始 BF16 为 0.00996–0.02389；完整 FP32 为约 1.65e-6–8.59e-6。融合方案没有消除 BF16 敏感度。单次算子时长不能外推为模型吞吐收益，batch 8/4 也不等于当前实际 expert batch 2。

## 算子约束

核对了 [Ascend 官方 GMM 数据类型约束](https://github.com/Ascend/op-plugin/blob/master/docs/zh/custom_APIs/torch_npu/torch_npu-npu_grouped_matmul.md)：A2 的普通非量化 BF16 输入对应 BF16 输出，`output_dtype` 并非任意精度开关。后续 FP32 输出方案必须验证所用算子和形状，不可仅修改这个参数就声称保留了累加精度。

所有诊断均使用原始数据、初始化和学习率。短跑或算子结果不替代 200 步验收；MTP 和 aux 同时保留加权日志口径与去权重口径。
