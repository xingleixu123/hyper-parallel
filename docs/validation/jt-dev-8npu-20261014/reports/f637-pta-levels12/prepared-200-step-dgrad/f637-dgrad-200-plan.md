# Linear 输入梯度 FP32：完整 200 步配对诊断计划

目标是判断三步样本中主 LM loss 差异缩小的现象能否维持 200 步，不据短步结果发布生产修复。当前用户目标优先主 loss；MTP/aux 继续记录，但不单独否决主 loss 候选，也不改它们的训练权重。

## 两组及共同条件

- `r129-f637-dgrad-fsdp8-fp32-200-v1`：新建匹配数值配方的 FSDP8 参考。
- `r129-f637-dgrad-cp2-fp32-200-v1`：相同配方的 CP2 对照。

两组均保持固定源码 `18602c4524dc664b81b2bad9a7b624455ce1494f`、JT_dev 基点 `f637ef7ee4d4b416800716f1ebaaae7709b8a06a`、原镜像/CANN 9.2.0-beta.2/PTA、数据、初始化、GBS8/MBS1、LR0.0001、专家 FP32 wgrad 和 Muon NS FP32。原生 BF16 Linear 前向不改，输入梯度用三步 C/D 已验证的 FP32 Linear 再转 BF16；普通权重梯度继续使用原生 BF16 autograd replay。两组都运行全新 1–200 步，关闭 checkpoint 写盘，避免产生无用途的大文件。

实际数学实现复用 `LinearInputGradient` / `TracedLinearInputGradient`，不另写第二份导数。新增观察器只记录每步实际反向分支次数与至多 128 种 shape；每步消费后清空，单 rank 单步记录不超过 64 KiB。不采集完整激活或参数 tensor。训练之前检查 CP1/2、TP1/EP1/PP1、8 卡拓扑和零起点。

## 验证顺序和判定

1. 在固定镜像、无 NPU 设备映射的 CPU 容器核对小矩阵 FP64 dX oracle、原生 wgrad/bias 梯度、冻结输入、不改变前向、逐步清空及非 BF16 bypass；用实际配置 parser 比对现有 200 步 resolved config，只允许 checkpoint 保存开关/目录变化。
2. 分别运行两组，每轮最多 900 秒，确认释放后至少间隔 1200 秒；若其他任务出现在选中卡上，只停止自己的容器。卡不足则等待，不缩减验收要求的卡数。
3. 核对全 8 rank 各 200 步完成、正常退出与释放、所有输入/初态/计数一致。分别将前三步同旧 C/D 的对应数值比较，以排查移除重型边界采集是否改变训练。
4. 只在两组都完整后计算新 FSDP8−新 CP2 的逐步主 LM loss 最大绝对差，阈值仍为 0.005。不能拿新 CP2 同旧原生配方基线混比，也不能拼接中断前缀。
5. 若主 loss 通过，再依据实际根因和维护成本设计生产实现并验证其他拓扑；若不通过，保存失败证据，不能宣称全矩阵达标。

此诊断的原生 wgrad replay 会额外计算，因此其时间只作诊断成本记录，不直接宣传生产性能收益。显存和时间仍记录，保留硬件、采集和原生配方不同的比较边界。FP32 head 临时内存的先前静态估算不是实测峰值。
