# 普通 Linear FP32 权重梯度：159 步前缀否决及后续二分定位

## 结论

**单独把普通 Linear 的权重梯度改为直接 FP32 累加，仍不能满足当前主 LM loss 的 0.005 要求。** 新 FSDP8 参考完整完成200步；匹配 CP2 在159步后出现其他任务，守卫停止自有容器让卡。比较共有1–159步、全部8rank，主 LM loss 最大绝对差为 **0.0178985595703125（第98步）**，第 **36步** 首次超过0.005。原配方在相同窗口最大差为0.011061668395996094。

已有前缀足以否决此候选，但**不是完整200步配对验收**。不补跑或拼接缺失的160–200步，不将MTP/aux作为本轮额外验收条件，不修改LR、loss系数或严格比较器。该候选未形成新的已确认产品根因，继续在总问题单Top1追踪，不据此新增生产修复PR。

## 改了什么、如何证明确实执行

固定129、集成源`18602c4524dc664b81b2bad9a7b624455ce1494f`，JT_dev基点`f637ef7ee4d4b416800716f1ebaaae7709b8a06a`包含#180/#186；镜像`sha256:5f9e677f439d11ab4e7c888f54b142335a27eee7411cbd2ce894a4798a70146d`，CANN9.2.0-beta.2。模型、数据、初始化、GBS8/MBS1、序长4096、LR0.0001、MTP0.3/aux0.0001均固定。

- FSDP8：200步×8rank，23个Linear每步覆盖，**38,400次实际FP32累加**；退出0，容器占用388.625秒，已释放。
- CP2：159步×8rank，23个Linear每步覆盖，**61,056次实际FP32累加**；在第160步完成前让卡，退出137，容器占用412.083秒，已释放，无自有残留PID。
- 两布局的三份数值helper逐字节相同；回调每步检查main_grad/flag已被FSDP消费，只保留有界标量与形状记录，不保存激活副本。未受模块范围管理的functional Linear仅记录到FP32路由计算。
- 每个布局首步前向各loss相对其原配方控制均差0；初始化、数据游标与输入身份、源提交、镜像、配置及逐步有限值校验通过。
- 无NPU的CPU合约用例5项与配置解析2项通过，包含实际HSDPParamV2梯度消费、混合梯度生产者、共享输出头和生产projected-cross-entropy重放。首轮CPU测试被TorchNPU默认checkpoint设备初始化挡住，随后仅在测试夹具内设置并恢复CPU默认设备类型，第二轮通过；没有删掉断言或改产品数学。
