# 真实 LM head 局部反向行切分诊断

## 目的与冻结条件

原生 FSDP/CP2 首步边界采样中，LM head 的输出梯度采样相同，输入梯度采样有少量差异。但原输入 hook 可能观察共享消费者的合流梯度，因此不能直接将差异归因于 head 矩阵乘。该实验固定真实输入、权重和输出梯度，用独立 autograd 重放 head 的局部输入梯度，检验行数变化的效应。

实验 `r129-f637-head-row-vjp-fsdp8-3-v1`，129、8 卡、端口30384，沿用已完成原生 FSDP 参考的源码18602c4、固定镜像、数据、初始化、BF16/FP32策略、LR及loss系数。配置只改训练为3步、关闭检查点写入及独立输出路径。设备占用守卫600秒，torchrun限时540秒；确认释放后全局等待1200秒。只使用空卡，发现他人任务后只停止本实验容器。

## 实际观测

- 仅rank0、首步、第一个LM head调用；前向后、FSDP恢复分片前，复制实际输入和完整权重。快照上限2GiB；本形状预计1,599,078,400字节。其余rank正常执行。
- 同一个真实输出梯度下比较：全4096行重算、两半2048行、每128行、两半零填充回4096行。每种方式覆盖全部20,971,520个输入梯度坐标；完整梯度只短暂留在CPU内存，不写盘。
- 独立CPU FP64 oracle只核对不超过8行×8列，沿全部词表维度求和，明确区别完整行比较和采样oracle。
- 观察hook返回None，不替换训练梯度，不改变功能函数。结束或失败及时释放输入/权重副本。日志只保存身份SHA、尺寸、有限统计与判定边界。

## 检查与解释

CPU5项检查覆盖：真实分块loss与共享LM/MTP头的数值透明性、所有行比较覆盖及精确小样例、失败清理、容量/不可微调用拒绝、已注册分片恢复hook之前快照。真实生产配置parser逐字段比较通过。无加速器初始化。加入备用存储路径检查后的资源守卫31项通过。

NPU完成后必须审计8rank恰好3步、输入/初始化/源码身份、完成与释放回执；对原生FSDP参考前三步比较LM、MTP、aux、total、梯度范数，透明性要求全部差0。最终200步验收器保持不变，3步结果不构成训练精度验收。

若局部行切分结果相同，继续核对完整上游梯度、loss缩放及共享分支合流；若不同，先利用填充对照和oracle进一步区分形状效应，再设计可逆的局部参考替换。任何干预必须以完整200步和相关续训复验确认，不能用强制替换最终参数的相等冒充根因。
